# VYTRON — Immersive 3D AI Landing Page

A fictional AI brand concept built as a portfolio piece: Next.js (App Router), React, TypeScript, Three.js, React Three Fiber, drei, GSAP ScrollTrigger, Motion for React (installed, reserved for UI), Lucide, custom CSS.

VYTRON is a fictional brand. Nothing on the page describes a real product.

## Quick start

```bash
npm install
npm run dev        # http://localhost:3000
```

Requirements: Node 20+ (built and tested on Node 22).

| Command | Purpose |
|---|---|
| `npm run dev` | development server |
| `npm run build` / `npm start` | production build / serve |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint (next/core-web-vitals) |
| `npm run blender` | run the Blender generator (needs `blender` on PATH) |

## The 3D core: GLB vs procedural

The core is a **procedural Three.js scene** (`components/three/`). It is the default and fully works with no model file.

`public/models/vytron-core.glb` is **optional**. It is generated by `scripts/create_vytron_core.py` in Blender (see `docs/BLENDER_GUIDE.md`). **This repository ships without that file**, because it was authored without Blender available. At build time `next.config.mjs` checks whether the file exists; if it does, the rings, lattice and glass layers come from the GLB, while the nucleus, neural network, pulses and particles stay live. If the file is missing or fails to load, the procedural core is used.

Rebuild (`npm run build`) after adding or removing the GLB.

## Contact form

No backend ships with the project, so the form never claims delivery it can't confirm. Configure one of these in `.env.local` (copy `.env.example`):

- `NEXT_PUBLIC_FORM_ENDPOINT` — e.g. a Formspree URL. The form POSTs JSON and reports success only on an HTTP 2xx answer.
- `NEXT_PUBLIC_CONTACT_EMAIL` — opens the visitor's mail app with the message prefilled (clearly worded as "not sent until you send it").
- Neither set — the form validates, then states that delivery is not configured and offers to copy the message.

Social links in the footer render only when `NEXT_PUBLIC_SOCIAL_*` URLs are set.

## Architecture

```
app/                    layout, page, global + section CSS
components/layout/      Experience (shell, loader, reveals), Navigation, Footer
components/sections/    Hero, Dimension, CoreSection, Capabilities, Process, Explorer, FinalCta, Contact
components/three/       Scene, CoreRig, materials, shaders, particles, GLB loader, live state
components/ui/          Wordmark, RevealLines, SectionLink, 2D WebGL fallback
lib/                    sceneState, scrollDirector (GSAP), modes, navigate, config
scripts/                create_vytron_core.py (Blender)
docs/                   BLENDER_GUIDE.md
```

How the scroll story works: `lib/scrollDirector.ts` uses GSAP ScrollTrigger only to *observe* scroll and map it to a pose (position, scale, rotation, lighting warmth, ring openness, node spread) pinned at anchors inside each section. The render loop damps the live pose toward that target, so natural scrolling is never intercepted. The 3D scene reads a mutable state object each frame, so there are no React re-renders for continuous motion. "Camera orbit" is implemented by rotating the structure, which looks identical from the viewer's side.

Performance choices: one fixed canvas, dynamic import of the scene (no SSR), DPR capped at 1.75 (1.5 on phones), reduced particle/node counts on phones, no post-processing (glow is faked with additive shader billboards), shader-driven particle motion, GSAP contexts reverted on unmount.

Accessibility: semantic landmarks, skip link, keyboard-operable controls (tabs with arrow keys, radiogroup, toggle buttons), visible focus rings, `aria-live` regions, `prefers-reduced-motion` support (instant reveals, near-static core).

## Testing

```bash
npm run typecheck && npm run lint && npm run build
```

Manual checks worth doing on a real GPU: scroll the whole page on desktop and a phone, try the Explorer modes, toggle OS "reduce motion", and disable WebGL (e.g. `chrome://flags`) to see the 2D fallback.

## Deploy to GitHub and Vercel

```bash
git init && git add . && git commit -m "VYTRON landing page"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

Then on vercel.com: **Add New → Project → import the repo**. Framework preset is detected as Next.js; no build settings need changing. Add the optional environment variables under *Settings → Environment Variables*, then redeploy. CLI alternative: `npx vercel`.

## Troubleshooting

- **Blank hero / no 3D:** your browser or GPU has WebGL disabled; the 2D fallback shows instead. Check `chrome://gpu`.
- **Headlines invisible:** JavaScript failed to hydrate; a failsafe reveals them after 5 s. Check the browser console.
- **GLB not used:** confirm the file is at `public/models/vytron-core.glb` and re-run `npm run build`.
- **Stale styles/chunks after rebuild (HTTP 400 on `_next/static`):** an old `next start` process is still running. Stop it and start again.
- **Scroll feels slow in a VM/headless browser:** software WebGL is slow; test on real hardware.
- **`npm install` peer warnings:** use `npm install --legacy-peer-deps` if your npm is strict.
